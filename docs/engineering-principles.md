# Engineering Principles

모든 구현 및 코드 수정에 다음 원칙을 적용한다.

## 1. 구현 전에 확인한다

추측하지 않는다.

- 전제나 가정이 있다면 명확히 밝힌다.
- 여러 해석이 가능한 요구사항을 임의로 선택하지 않는다.
- 더 단순한 방법이 있다면 먼저 검토한다.
- 요구사항이 불명확하면 범위를 임의로 확대하지 않는다.

## 2. 단순함을 우선한다

문제를 해결하는 데 필요한 최소한의 코드를 작성한다.

- 요청하지 않은 기능을 추가하지 않는다.
- 한 번만 사용되는 코드를 불필요하게 추상화하지 않는다.
- 미래의 확장 가능성을 가정해 복잡성을 추가하지 않는다.
- 현실적으로 발생하지 않는 상황을 위한 방어 코드를 과도하게 추가하지 않는다.

## 3. 필요한 부분만 수정한다

모든 변경은 현재 작업과 직접적인 연관성이 있어야 한다.

- 관련 없는 코드, 주석, 포맷을 정리하지 않는다.
- 문제가 없는 코드를 취향에 따라 리팩터링하지 않는다.
- 기존 프로젝트의 스타일과 패턴을 우선한다.
- 변경으로 인해 새롭게 사용되지 않게 된 코드만 정리한다.

## 4. 검증 가능한 목표로 작업한다

작업을 완료 조건으로 변환한다.

예:

- 버그 수정 → 재현 가능한 테스트 또는 검증 방법을 확인하고 수정 후 통과시킨다.
- validation 추가 → 잘못된 입력이 거부되는 것을 검증한다.
- 리팩터링 → 기존 동작이 유지되는 것을 검증한다.

여러 단계가 필요한 경우 구현 전에 짧은 계획을 세운다.

```text
1. [작업] → 검증: [방법]
2. [작업] → 검증: [방법]
```

검증되지 않은 상태를 완료로 간주하지 않는다.
